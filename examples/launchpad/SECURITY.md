# 예제 5 보안 노트 — 본딩 커브 런치패드 (`BondingLaunchpad`)

## 자금 보관

**커브가 quote와 커브 토큰 전량을 보관**한다. 졸업 시 전액이 AMM 페어로
이전되고, 이후에는 페어가 보관한다. 런치패드에 상주하는 운영 예치는
없다 — treasury 수수료는 발생 즉시 이체된다.

## F-01..F-08 매핑

| 항목 | 이 예제와의 관계 |
|---|---|
| **F-01** 예치 재진입 | buy/sell/graduate 전부 `nonReentrant`. 유입은 pull(도착량 측정)이고 지급은 push — 외부 호출 사이에 커브 상태가 없어(F-02 참조) 재진입 이득이 성립하지 않는다. |
| **F-02** fee-on-transfer | quote·커브 토큰 유입 전부 `SafeToken.pull`의 **도착량(delivered) 기준**. FoT quote로 매수하면 세금·가격 전부 도착량으로 정산된다 (실측 테스트). treasury가 FoT를 받을 때의 재과징(9.9 송금 → 9.801 도착)은 좌초가 아니라 리저브 편입이다. |
| **F-03** 무코드 토큰 | 생성자가 quote/AMM 팩토리의 `code.length`를 검사. 토큰 이동은 SafeToken(무코드 거부 + strict bool). |
| **F-04** 무한 view | 뷰는 전부 상수 시간(잔액 조회 + 산술). 순회 없음. |
| **F-05** EIP-7702 | 수신 콜백 경로가 없다(ERC-20만). 위임 코드 보유 EOA도 커브 입장에서 일반 호출자. |
| **F-06** 단일 registrar | 무관. 런치패드는 단일 배포·단일 졸업 — 지속 등록 기능이 없다. |
| **F-07** 오픈 로그 ≠ 승인 | `Bought`/`Sold` 이벤트는 누구나 읽지만 권한과 무관. 커브 토큰 잔액이 유일한 권리 증명. |
| **F-08** randomness | 무작위 요소 없음. 선착순은 블록 순서가 결정. |

## 핵심 불변식

```
1. 유효 리저브 곱: vq * vt 는 매매로 줄지 않는다
   (fee/스나이프 세금은 커브 밖으로 나가므로 곱에 들어가지 않는다)
2. 왕복 비차익: buy(x) → 즉시 전량 sell → 수령 < x (fee 2회 + 슬리피지)
3. 졸업 후 커브 잔액 == 0 (전액 페어 이전, LP는 dead 잠금)
```

1·2는 fuzz(256 runs CI / 5000 runs 로컬)로 매 거래 검증한다.

## brake 매트릭스

| brake | buy | sell | graduate |
|---|---|---|---|
| 0 | 허용 | 허용 | 허용 |
| 1 | 차단 (BrakedNewEntry) | **허용** | 차단 (페어 생성은 진입) |

graduate를 진입으로 분류한 이유: 졸업은 자산을 새 컨트랙트(페어)로
옮기는 신규 진입이며, brake 중 졸업하면 페어의 swap도 팩토리 brake에
막히기 때문에 규제 목적이 무색해진다. brake 중에도 커브 매도로 탈출은
열려 있다 — 갇힌 자금 없음.

## 이 예제 고유 위험과 완화

| 위험 | 완화 |
|---|---|
| **페어 선점 공격** — (토큰, quote) 페어를 미리 만들고 소량 LP를 심어 졸업 유동성의 대부분을 훔치기 | `graduate()`가 기존 페어를 재사용하는 조건은 `totalSupply() <= 1000`(dead 잠금분뿐). 초과 예치가 있으면 `PairPoisoned`로 거부. **배포자는 quote로 미리 페어가 만들어지는지 감시할 것** — 감시 실패 시 그 토큰의 졸업은 영구 불가. |
| **졸업 프론트런** | 무해하다 — graduate는 무차별 public이고 호출자가 아무것도 수령하지 않는다 (LP 전량 dead). |
| **스나이프 세금 회피** (launch 직전 매수 대기 → 세금 구간 종료 후 일제 매수) | 감쇠 세금은 시간이 아니라 **진입량의 함수** — 첫 매수 물량이 커지면 슬리피지가 같이 처벌한다(커브 스프레드). perBuyerCap이 병행 방어. |
| **cap 다중 주소 우회** | 완화책일 뿐이다. Sybil 저항이 필요하면 이름/신원 연동(예제 15)을 앞단에 두되, 그 순간 허가제 런치패드가 되므로 법적 검토 범위가 넓어진다. |
| **treasury 남용** | fee/스나이프 세금의 수령인은 immutable — 배포 시 결정. 다중 서명(예제 8)으로 지정하는 것을 권장. |
| **floors·target 산수 오류** | target이 k0/tokenFloor − quoteFloor을 초과하면 졸업이 수학적으로 불가능. 배포 전 검증 스크립트/시뮬레이션 권장. |
| **졸업 페어 가격 조작** | 졸업 순간 페어 리저브 = 커브 최종 리저브 — 단일 tx에서 이전되므로 조작 창이 없다. 이후 조작은 AMM 예제의 TWAP 권고를 따른다. |
| **LP 영구 잠금** | dead 잠금은 의도된 것이다. 회수 가능 구조로 바꾸면 졸업 프론트런·운영 리스크가 되살아난다(README 경고). |

## 퍼짱으로도 못 밝히는 것

- 밸리더의 블록 순서 조작 (선착순 매수 순서) — perBuyerCap·세금이
  완화할 뿐.
- quote 토큰 자체의 신뢰성 (발행·동결 권한이 발행자에게 있는 quote는
  커브 전체를 통제한다 — 예제 1처럼 고정 공급 quote를 권장).
- 관할권 법률 (README 법적 고지).
