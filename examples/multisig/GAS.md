# 예제 8 가스·상태 비용 — 단순 멀티시그

측정 환경: forge 1.6.0-nightly (5e88010), solc 0.8.24, optimizer 200 runs,
evm paris. 원본: `forge test --match-path 'test/multisig/*' -vv`.

## 현재 측정치 (2026-10-08, EIP-712·ERC-1271 지원)

### 배포 (소유자 5, threshold 3)

| 연산 | gasUsed | 코드 B | 상태 units |
|---|---:|---:|---:|
| SimpleMultisig 배포 | 1,327,101 | 5,944 | **6,544** |

### 실행

| 연산 | gasUsed | 새 슬롯 | 로그 B | 상태 units |
|---|---:|---:|---:|---:|
| execute (EOA 서명 3개, 1 ether 송금) | 86,085 | 1 | 256 | **108** |

EIP712·SignatureChecker와 혼합 승인 API로 배포 코드가 커졌다. 배포 units는
StateMeter의 코드 바이트와 소유자 mapping 등 배포 상태·로그 계량의 합이다.
immutable 값은 별도 storage 슬롯을 소비하지 않는다. 오프체인 실행의 새
슬롯 1 = `executed[hash]` 첫 기록 — **이 경로의 유일한 상태 증가**다.

위 실행은 기존 EOA 서명 배열 경로다. ERC-1271 검증 gas는 계정 정책과
체인의 P-256 구현에 따라 달라진다. mock은 Paris EVM에서 Solidity P-256을
쓰므로 mock 테스트 gas를 실제 EastSea 계정의 체인 gas로 해석하지 않는다.

### 직접 승인

처음 승인하는 소유자·digest마다 `approvals[hash][owner]` **1슬롯과
Approved 이벤트**가 추가된다. 같은 소유자의 같은 digest 재승인은 새 슬롯을
만들지 않는다. 실행·만료 후에도 승인 슬롯은 남는다. 직접 승인 gas·전체
units는 별도 계량하지 않았으므로 **108u는 승인 트랜잭션을 포함한 비용이 아니다.**

### 이전 측정치 (historical, 2026-10-06)

ERC-1271·EIP-712·직접 승인 추가 전 `ecrecover` 전용 버전은 배포
576,907 gas / 2,202 코드 B / 2,802u, EOA 실행 71,298 gas / 108u였다.
이 값은 현재 배포 비용이 아니다.

## 온체인 컨펌 모델과의 비교 (왜 오프체인 서명인가)

3-of-5에서 **모든 승인을 오프체인에서 수집한 경우**의 비교다.
온체인 컨펌 열은 설명용 추정치다:

| 단계 | 온체인 컨펌 (비트맵 모델) | 이 예제 |
|---|---:|---:|
| 제안 (tx 레코드 슬롯) | ~100u | 0 (오프체인) |
| 컨펌 3건 (각 트랜잭션 로그+비트맵) | ~330u | 0 (오프체인 서명) |
| 실행 | ~108u | **108u** |
| **tx 1건 합계** | **~540u** | **~108u** |

컨펌 3건의 gas(트랜잭션 자체)는 물론 이 예제가 0이다 — 서명은
지갑에서 나온다. 체인 비용은 실행 순간에만 발생한다.

연간 시나리오 — 주 5건 실행:

| 모델 | 연간 상태 units |
|---|---:|
| 온체인 컨펌 | 540 × 260 = 140,400 |
| 이 예제 | 108 × 260 = 28,080 |

## 설계 시사점

- **오프체인 실행은 108u다.** 서명 개수가 늘어도 상태는 해시 1슬롯이며,
  검증 gas는 EOA·계약 계정 정책과 서명 수에 따라 증가한다.
- 직접 승인은 추가 유료 상태를 쓰지만 오프체인 서명이 없는 EastSea
  지갑도 실제 계정 트랜잭션으로 공동 승인에 참여할 수 있게 한다.
- 유료 상태 체인에서 "컨펌을 어디에 두는가"가 아키텍처를 결정한다.
  서명이 오프체인에 있으면 체인은 집행 기록만 남는다 — 이것이
  이 예제의 존재 이유다.
- `executed[hash]`는 임의 nonce의 병렬 작업을 전체 digest 단위로 구분한다.
  순차 nonce 카운터로 교체하면 승인·재발의 순서 규칙이 바뀌므로 클라이언트
  흐름을 함께 검토해야 한다.
