# 예제 14 — 커밋-리빌 래플

> ⚠️ **법적 고지 — 공개 배포 전 법률 검토 필수.** 참가비를 받아
> 우승자에게 몰아주는 구조는 관할에 따라 복권·도박·게이밍 규제의
> 대상이며, 상당수 관할에서 라이선스 없이는 **불법**이다 (GAMBLING
> ADJACENT). 무료 응모(참가비 0)로 운용하려면 ticketPrice 구조를
> 다시 설계해야 한다. 이 예제는 기술 견본이며 법률 자문이 아니다.

티켓 판매로 풀을 모으고, 주최자는 **참가 모집 전에** 시드를 해시로
커밋해 둔다. 참가 마감 후 시드를 공개하면 우승 인덱스가 정해진다.

| | prevrandao 단독 | 시드 단독 | 혼합 (이 예제) |
|---|---|---|---|
| 조작 주체 | 블록 제안 검증자 | 주최자 | **어느 쪽도 단독 불가** |
| 공격 | 제안자가 결과 시뮬레이션 | 유리한 시드만 공개 | 시드는 모집 전 커밋, 검증자는 시드를 모름 |
| 남는 위험 | — | 리빌 거부 | 검증자+주최자 합작 (경제적 이득 희박) |

**핵심 설계 — 무작위성은 두 주체의 합작이어야 한다 (F-08).**
체인에는 안전한 난수가 없다. 그래서 두 개의 "못 믿는" 소스를
섞는다:

```
winner = players[ hash(seed ⊕ block.prevrandao) % N ]
```

- **주최자 시드**: 생성 시점에만 존재하고, 배포 때는
  `keccak256(seed)`만 체인에 박힌다. 참가자 명단이 확정되기 전의
  약속이라 주최자는 특정 참가자를 겨냥할 수 없다.
- **prevrandao**: 리빌 트랜잭션이 들어간 블록의 제안자 난수.
  주최자도 미리 알 수 없다.
- 시드를 아는 주최자는 prevrandao를 못 고르고, prevrandao를 고르는
  검증자는 시드를 모른다 — 단일 주체 조작이 구조적으로 막힌다.

**리빌 거부(withholding)의 완결 보장.** 주최자가 "내가 안 이긴다"를
알고 리빌을 거부하면? 리빌 마감 후 **누구나** `drawWithoutSeed()`로
prevrandao만으로 추첨을 강행한다. 주최자의 시드는 버려지지만 상금은
반드시 참가자에게 간다 — "안 뽑힌 채로 굶는" 풀이 없다.

**1회성 라이프사이클.** 추첨은 되돌릴 수 없다. 그래서 이 컨트랙트는
라플 하나가 배포 하나다 — 재추첨 키를 만드는 대신 다음 회차를 새로
배포한다. 되돌림 가능성 자체가 조작 표면이다.

## 함수표

### `CommitRevealRaffle` (guardian, seedCommit, ticketPrice, enterPeriod, revealWindow)

| 함수 | 호출자 | brake | 효과 |
|---|---|---|---|
| `enter()` (payable) | 누구나 | 진입 차단 | 티켓 1장. 여러 장은 여러 번 |
| `reveal(seed)` | **누구나** | 무관 | 참가 마감~리빌 마감. 커밋 매칭 → 추첨·지급 |
| `drawWithoutSeed()` | **누구나** | 무관 | 리빌 마감 후 강행 추첨 (시드 버림) |
| `players(i)` / `playerCount()` / `winner()` | 뷰 | — | 상수 시간 |

리빌이 "누구나"인 이유: 시드는 calldata로 한 번 공개되면 공개
정보다 — 주최자가 굳이 직접 호출할 필요가 없다 (주최자 지갑이
오프라인이어도 추첨이 완결된다).

## 배포

```bash
# 1) 시드 생성 — 아무도 모르게, 오프라인에서
SEED=$(cast rand 32)
COMMIT=$(cast keccak $SEED)   # abi.encodePacked(seed)와 같은 32바이트 해시
# ⚠ 시드를 잃으면 리빌 마감 후 drawWithoutSeed로 추첨된다 — 백업 필수

forge create src/raffle/CommitRevealRaffle.sol:CommitRevealRaffle \
  --constructor-args $GUARDIAN $COMMIT 1000000000000000000 604800 259200 \
  --rpc-url $RPC --private-key $DEPLOYER
# ticket 1 EAST, 참가 7일(604_800s), 리빌 창구 3일(259_200s)
```

- `seedCommit`: 배포 후 변경 불가. 커밋 시점이 참가 모집보다
  **앞선다**는 것이 보안의 전부다 — 이미 모인 명단을 보고 시드를
  고르면 이 설계는 무너진다.
- 참가비는 immutable — 진행 중 가격 변경·환불 정책 변경 키 없음.
- 상금은 풀 전액(티켓 수 × 가격)을 우승자에게 즉시 지급 —
  별도 청구 트랜잭션이 없다.

상태 비용 요약 (측정 환경·전체 수치는 [GAS.md](GAS.md)):

| 항목 | units |
|---|---:|
| 배포 (커밋·마감·가격 immutable) | 3,480u |
| 첫 티켓 (players 원소 + 길이 슬롯 최초) | 206u |
| 추가 티켓 | 106u |
| reveal (추첨 + 상금 지급) | 106u — **추첨이 참가보다 싸다** |

## 커스터마이징 경고

- **시드를 여러 번 쓰지 마라** — 같은 주최자가 같은 시드로 여러
  라플을 열면 첫 리빌 이후 시드가 공개되어 나머지 라플의 시드
  소스가 죽는다 (prevrandao만 남는다). 회차마다 새 시드.
- **참가자가 티켓을 되사는 구조**(중복 참가 허용은 이 예제의
  설계)에서 "취소·환불"을 붙이면 마지막 티켓 취소로 배열이
  변한다 — 되돌림 금지 원칙상 취소 없이 1회성으로 쓰는 게 맞다.
- **N% 수수료를 주최자에게** 떼는 순간 도박 규제 노출이 커진다
  (하우스 엣지). 무료 추첨·후원 상금 모델이면 예제 13과 조합.
- **prevrandao 의존 확대**(시드 없는 운용)는 F-08 위반 사례 그
  자체다 — drawWithoutSeed는 어디까지나 리빌 거부의 완결 보장용.
