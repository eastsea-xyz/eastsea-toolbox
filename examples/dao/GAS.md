# 예제 11 가스·상태 비용 — 단순 DAO

측정 환경: forge 1.6.0-nightly (5e88010), solc 0.8.24, optimizer 200 runs,
evm paris. 원본: `forge test --match-path 'test/dao/*' -vv`.

## v2 측정치 (2026-10-08)

EIP-712 + OpenZeppelin SignatureChecker + 직접 vote 경로의 현재 코드
계량이다. 2026-10-06의 v1 수치(배포 4,743u, execute gas 67,721)는
`personal_sign`/ecrecover 전용 코드의 과거 기준이며 v2 배포 견적으로
사용하지 않는다.

### 배포

| 연산 | gasUsed | 코드 B | 상태 units |
|---|---:|---:|---:|
| SimpleDAO v2 배포 (guardian, token, quorum, 3기간) | 1,655,892 | 7,898 | **8,198** |

### 수명 주기

| 연산 | gasUsed | 새 슬롯 | 로그 B | 상태 units |
|---|---:|---:|---:|---:|
| propose (해시 커밋) | 50,489 | 2 | 256 | **208** |
| 투표 1건 (오프체인 서명) | 0 | 0 | 0 | **0** |
| 직접 vote 1건 | 23,670 | 1 | 160 | **105** |
| execute (EOA 서명 5개, 국고 지출) | 91,538 | 0 | 224 | **7** |
| executeWithSigners (직접 승인 1개, target.record 호출) | 66,215 | 0 | 224 | **7** |

원본 meter는 기존 `SimpleDAO.t.sol`의 배포·서명 수명주기와
`SimpleDAO1271.t.sol:test_meter_directVoteAndApprovedExecution`의 직접
투표 경로다. gas는 각 fixture의 대상 호출까지 포함하고, 상태 units는
DAO 주소만 추적한다. ERC-1271 gas는 signer 구현에 달려 있다: 테스트
EastSea fixture는 실제 P-256을 Solidity로 검증하며 EastSea의 네이티브
P-256 검증 비용을 이 표에서 추정하지 않는다.

새 슬롯의 정체:
- propose 2 = `Proposal` 구조체 — executionHash 1슬롯 + 타임라인
  팩(uint48×3 + bool) 1슬롯. `nextProposalId` 재기록은 계정 first-write
  로만 첫 제안에 붙는다.
- execute 0 = `executed` 플래그는 기존 팩 슬롯 안 재기록. 서명
  검증(SignatureChecker × N + balanceOf × N)은 실행 gas일 뿐
  상태를 만들지 않는다.
- 직접 vote 1 = `approvedVotes[proposalId][msg.sender]` bool 1슬롯.
  승인 당시 잔액이나 총 무게는 기록하지 않는다. 서명과 직접 승인을
  섞어 실행해도 주소별 현재 잔액을 한 번만 합산한다.

## 프로그램 시나리오 — 참여 규모별 비교

온체인 투표(Governor 계열)는 투표 1건이 유권자 슬롯 1개(~100u)다.
다음 비교는 이 DAO의 **서명 경로**이고 배포 비용은 제외한다:

| 시나리오 | 이 예제 (서명 경로) | 온체인 투표 |
|---|---:|---:|
| 제안 100건 | 100 × 208u = 20,800 | 100 × ~300u = 30,000+ |
| 투표 10,000건 (제안당 100명) | **0** | 10,000 × ~100u = 1,000,000 |
| 실행 100건 | 100 × 7u = 700 | 100 × 7u = 700 |
| **합계** | **≈ 21,500** | **≈ 1,030,000** |

서명 경로는 참여 1만 규모에서 **약 48배**. 온체인 투표의 상태는 모든 토큰
보유자가 함께 내는 반면, 이 설계의 서명 수집 비용은 relayer의
오프체인 저장소와 실행 트랜잭션 1건이다. 투표 비밀성·실시간
집계가 필요 없다면 서명 투표가 유료 상태 체인의 정답에 가깝다.

직접 투표 10,000건이면 승인 비용만 10,000 × 105u = 1,050,000u다.
이 경로는 오프체인 서명을 지원하지 않는 지갑을 위한 호환성 선택이며,
0슬롯 서명 경로의 상태 절감 수치가 적용되지 않는다.

## 설계 시사점

- **제안 208u가 프로그램의 지배 항**이고, 그 중 대부분은 해시 커밋
  1슬롯이다. calldata를 통째로 저장하는 설계라면 제안 길이에 비례해
  상태가 늘어난다 — 해시만 남기고 전문을 오프체인에 두는 것이
  커밋의 이유다.
- **execute 7u = 로그만**. 쿼럼·서명 검증·국고 전송이 전부 실행
  gas로만 소비된다. 일회 실행 플래그는 제안의 기존 타임라인 슬롯
  안에서 재기록한다.
- 무게를 실행 시점에 읽는 선택(`balanceOf`)이 이 구조를 가능하게
  한다 — 체크포인트 토큰이라면 계좌당 슬롯이 쌓이고 이 표는
  무의미해진다. **정확성(스냅샷)과 상태 비용(잔액)의 교환**이
  예제의 중심 교훈이다.
