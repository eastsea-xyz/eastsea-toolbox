새 슬롯의 정체:
- 첫 티켓 2 = players[0] 원소 1슬롯 + 배열 길이 최초 기록 1슬롯.
  이후 티켓은 원소만.
- reveal 1 = `winner`(address) + `drawn`(bool)가 한 슬롯에 팩 —
  추첨의 영구 기록은 이 1슬롯이 전부다.
- reveal의 gasUsed(34,317)가 추가 티켓(33,538)과 비슷한 이유:
  증명 검증이 없는 대신 해시 1회 + 모듈로 산수 + 상금 전송.
  **상금 지급 포함 추첨이 티켓 1장보다 싸다.**

## 프로그램 시나리오 — 티켓 1,000장

| 항목 | 건당 | 합계 |
|---|---:|---:|
| 배포 | 3,480u | 3,480 |
| 티켓 1,000장 | 첫 206u + 106u × 999 | ≈ 106,200 |
| reveal (추첨·지급) | 106u | 106 |
| **라플 1회 총계** | | **≈ 109,800u — 다음 회차는 새 배포** |

1회성 라이프사이클이므로 상태가 누적되지 않는다: 매 회차 약
11만u가 새로 생기고 이전 회차는 그대로 굳는다(우승자·참가자
기록). N회 운용의 총 상태는 ≈ N × 11만u — 회차를 거듭하며
정리해 주는 상태가 없는 대신, 회차별 원장이 독립적으로 남아
"어느 회차에 누가 얼마를 받았나"가 영구 보존된다.

대안 비교 — "재사용형 래플"(winner 리셋·players 초기화 키):

| 항목 | 1회성 (이 예제) | 재사용형 |
|---|---:|---:|
| 회차당 배포 | 3,480u | 0 (1회) |
| 회차 전환 | 새 배포 (가스 ~71만, 상태 3,480u) | 리셋 tx (전원 소거 가스) |
| 재추첨 키 | **없음** | 존재 (리셋 남용 = 조작 표면) |
| 회차 독립성 | 컨트랙트 주소가 다르다 | 공유 (회차 간 버그 전파) |

티켓 1,000장 규모에서 회차당 배포 상태 3,480u는 참가 상태의 3%다
— 1회성의 단순함이 상태 절약보다 크다.

## 설계 시사점

- **참가자 슬롯은 배열이 최소다**: 매핑(주소→티켓수)은 중복 참가
  정책과 취소 정책이 얽히고, 열거가 불가능하다. 배열 push는
  순서(곧 우승 인덱스의 정의역)를 보존한다.
- **추첨의 상태는 1슬롯**: winner+drawn 팩이면 충분하다 —
  "언제 어떤 해시로 뽑았는지"는 이벤트(Drawn의 mixedSeed)에
  있다. 검증은 이벤트 스캔으로, 진실은 슬롯으로 (F-07).
- **상금 즉시 지급이 청구보다 싸다**: 별도 claim 트랜잭션(우승자
  슬롯 + 크로스체인 대기)이 없다. 우승자가 call을 받을 수 있는
  주소라는 가정만 지키면 된다.
