# 예제 4 가스·상태 비용 — AMM

측정 환경: forge 1.6.0-nightly (5e88010), solc 0.8.24, optimizer 200 runs,
evm paris. 원본: `forge test --match-path 'test/amm/*' -vv`.

## 시나리오 근사: 풀 하나의 수명

| 시점 | 누적 units |
|---|---:|
| 팩토리 배포 (1회) | 10,591 |
| + 페어 10개 생성 | +10 × 8,496 ≈ 84,960 |
| + 페어당 초기 유동성 | +10 × 423 ≈ 4,230 |
| + 일일 스왑 1,000건 × 30일 (스왑당 32u) | ≈ 960,000 |

**스왑 트래픽이 상태 비용의 대부분을 만든다** — 슬롯이 아니라 로그
때문이다. 스왭 1건 = 32 units(로그 1,024B ÷ 32 + 원본 0). 유료 상태
모델에서 AMM의 지속 비용은 거래량에 비례한다. 로그 토픽을 줄이는
것(Swap 이벤트 6개 필드 → indexed 3개 유지)이 비용 최적화의 지렛대.

## 설계 시사점

- **리저브 팩(uint112×2+uint32)이 슬롯 1개를 아낀다** — 전통 Uniswap
  레이아웃 그대로. TWAP 적산 2슬롯은 오라클의 대가.
- **스왑 newSlots 0**: 리저브는 기존 슬롯 갱신(유료 아님), 유입/지급
  잔액은 토큰 쪽 슬롯. AMM은 유료 상태에서 가장 저렴한 고빈도 패턴.
- **burn은 클리어라 30u뿐** — 회수가 싸다는 것은 탈출 장벽이 없다는
  뜻 (brake 설계와 일관).
- removeLiquidity의 2슬롯/249u는 ERC-20 승인 갱신과 LP 소각 이벤트
  분이다 — 구조적으로 불가피.
