# 예제 17 보안 — Kelp Kiosk (에이전트 자판기)

## 위협 클래스 회피 (F-01 … F-08)

| 클래스 | 이 예제의 회피 |
|---|---|
| **F-01** 재진입 | `deliver`/`refund` CEI — `delete orders[id]`·이벤트가 전송보다 앞. 재진입(수신 컨트랙트 지갑) 시 주문이 이미 없다. `nonReentrant` 이중 안전. |
| **F-02** 수수료-온-전송 토큰 | native AETH만 다룬다. |
| **F-03** 무코드 토큰 | 토큰 없음. `receive()`는 `PaymentNotAllowed` — 지불은 `order(specHash)`뿐이라 잔액 추적 토큰이 될 수 없다. |
| **F-04** 비례 뷰 순회 | 순회 없음 — 주문 id 직접 조회. 통계(배달률·분쟁)는 이벤트 스캔의 영역. |
| **F-05** 7702 위임 | 주문·환불의 판정은 `msg.sender`·`msg.value`뿐. 위임 계정이 어떤 코드를 깔아도, 아예 에이전트 컨트랙트가 주문해도 규칙 동일. |
| **F-06** 단일 registrar | 없다. 가격·기한·에이전트 전부 immutable. 상품 관리·재고·차단 목록 키가 존재하지 않는다. |
| **F-07** 오픈 로그 ≠ 승인 | `Delivered`는 "기한 내 해시가 등록됐다"만 말한다 — 품질 승인이 아니다. 진실은 슬롯 부재(완결)와 정산 사실뿐. **이 예제의 주제다.** |
| **F-08** 무작위성 | 없음. |

## brake 범위

`order`(진입 — 새 지불 약정)만 `whenEntryOpen`으로 차단.
`deliver`·`refund`(탈출)는 항상 개방 — brake를 걸어도 진행 중인
주문의 돈은 반드시 에이전트 또는 주문자 중 한쪽으로 나간다.

## 불변식 (테스트로 검증)

- **I1 — 정산은 배달 수와 비례**: `agent.balance == 배달 건수 ×
  price` (fuzz: 임의 분기 조합).
- **I2 — 환불은 전액**: 환불자 잔액은 원금 회복. 컨트랙트가
  보유하는 것은 진행 중 주문의 정가뿐 — 수익 구조가 없다.
- **I3 — 원장 부재 일치**: 살아남은 슬롯은 방치(미배달·미환불)
  주문 수와 정확히 같다 (fuzz 전수 검사).
- **I4 — 완결의 일방성**: 배달된 주문의 `refund`, 환불된 주문의
  `deliver`, 이중 환불은 모두 `UnknownOrder` — 슬롯 부재가 답이다.

## 고유 위험

| 위험 | 성격 | 완화 |
|---|---|---|
| **쓰레기 배달** | 에이전트가 아무 해시나 등록해도 정산된다 — 심사가 없다. | 설계상 의도된 특성. 방어는 온체인 밖 평판(Delivered 로그 스캔)과 에이전트 교체(새 배포). |
| **마감 직전 경쟁** | `due` 경계의 배달/환불은 블록 타임스탬프 기준 — 근거가 이벤트에 남는다(`DeliveryTooLate`/`StillOpen` 파라미터). | 마감은 넉넉히. |
| **spec/result 해시 조작** | 로그의 해시는 원문을 증명하지 않는다 — 원문 공개는 당사자 책임. | spec 원문을 공개 IPFS 등에 두고 해시로 커밋하면 로그가 가리키는 증거가 완성된다. |
| **주문자가 재진입 컨트랙트** | `refund`의 전송을 받는 주소가 악의적이어도 슬롯은 이미 삭제돼 있다. | CEI로 봉쇄 (테스트 커버). |
| **에이전트 키 유출** | 키 홀더가 임의 `deliver`로 정산만 할 뿐 인출할 잔고가 없다(컨트랙트는 들어온 value를 바로 넘긴다). | 피해 상한 = 미배달 주문들의 정가 — 전부 `refund`로 회수 가능. |
| **가격 오책정** | 정가가 시장과 동떨어져도 immutable — 못 고친다. | 새 배포가 유일한 경로 (주소가 곧 가격표). |

## CEI 세부 — delete가 먼저다

`deliver`·`refund` 모두 (1) 슬롯 읽기·검사 (2) `delete orders[id]`
(3) 이벤트 (4) 전송 순서. 수신 콜백에서 재진입해도 `UnknownOrder`만
만난다 — 상태를 겹쳐 쓸 창이 없다.

## 남는 신뢰 가정

- 온체인은 기한과 금액의 이행만 보증한다. **품질의 담보는
  평판 시스템**이다 — 이 컨트랙트는 그 데이터(Delivered 로그)를
  위조 불가능하게 남긴다.
- 에이전트 주소가 native를 받을 수 있어야 `deliver`가 성공한다
  (실패 시 `PayoutFailed`, 주문자는 기한 후 `refund`로 회수).
